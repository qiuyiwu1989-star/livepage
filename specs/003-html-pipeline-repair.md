# 003 HTML 转换管线整改计划

2026-10-14 · 用户已授权制定计划；实施范围按以下阶段推进。

## 目标
将存量课件变成来源可追溯、视觉忠实、关键元素可编辑、可用于备课和播放的页面版本。先修通用管线，再扩大转换。HTML数量不是完成指标。

## 不做
不全库重跑、不覆盖原件/既有HTML/课程历史、不顺手重新设计、不把整页图片包装称为可编辑转换、不提前部署、不替用户确认AI知识。

## 分工
Codex负责来源、结构协议、提取器、渲染器、测试与制品对照。MiMo 2.6 Flash经DeepSeek harness处理可见文字核验、语义分组和复杂结构候选；不是几何和事实真源。用户裁定设计差异和最终样板接受。harness端点/实际模型ID/任务协议未核验前不发批处理。

## P0 本地预览与来源基线
- 核对已启动5318预览与当前代码；本次入口请求返回302，仅证明入口响应，不等于完整流程验收。
- 保留本地46页样本及已有UI优化，接入四张代表页对照，私有资料位于仓库外。
- 每页记录atom_id、occurrence、原件/导出PDF/原图哈希、PDF选定build、旧HTML及内嵌JSON、生成器版本。
- 不按页码或标题推断同源；找不到准确源版本则blocked。
- 产物：source-manifest.json、旧产物快照、可复现本地对照入口。
- 验收：四页来源能逐项回溯，私有文件未进公开Git，其他会话成果未被覆盖。

## P1 先建立验收闸
- 区分generated、render_checked、visual_review_pending、accepted、failed/blocked。
- 必需素材缺src/文件缺失、异常字符未解决、关键块缺失即blocked，不能只打印warning后交付。
- 验收记录绑定源/JSON/HTML哈希、截图、生成器与审阅范围；保留历史human-reviewed标记但不自动升级新状态。
- 缺失比例必须可解释；无效计数和未配对行不能当通过证据。
- 产物：校验器、失败报告、合成缺图/乱码回归测试。

## P3 字体、嵌入与性能
- 将已完成字体子集工具挂入转换后处理；保留完整源字体以支持后续增字重打包。
- 比较字体覆盖/字宽以及可见换行；字体瘦身不等于原稿忠实度验收。
- 固定1920×1080基准截图，并检查内嵌与全屏；等待字体和图片完成后核验。
- 测量冷/热请求、文件体积和显示时序；当前页不等待全目录，重复切HTML不重新加载。
- 产物：前后体积/时间/视觉报告。不得以文件缩小比例冒充用户加载时间改善。

## P4 harness接入与12页小批
- 读取现有harness任务配置/接口，确认实际MiMo模型ID、输入输出协议、费用与并发约束。
- 先对账已存在任务，不重复创建；以源哈希+规范+生成器版本识别重试。
- 模型只输出候选sidecar；不改canonical ID，不自行填写human_confirmed。
- 四页通过后从剩余样本补到12页，覆盖文字/卡片/表格/流程关系/图文混排；不一次全库。
- 任务登记独立记录排队/运行/失败/制品，失败保留已完成阶段。
- 验收：12页逐页有问题清单和可见证据，无静默缺图或乱码；失败页保持原图可用。
