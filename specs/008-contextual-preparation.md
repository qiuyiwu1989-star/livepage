# 008：有上下文的备课台

日期：2026-10-15。用户授权持续实现、检验，直到有可满意验收的成果。

## 要什么
输入主题、听众、时长和讲者意图后，主动查深脑原文、著作目录与章节、历史资料，先形成可纠正的授课理解。确认后推敲讲述，再生成带来源的讲稿与选材建议。旧组装保留，独立备课方案不改写母课。

## 本轮交付
- 专门的备课页面：意图→上下文与理解→修正/确认→讲述提案→完整讲稿。
- 深脑官方API只读适配（当前提供的是HTTP API，不冒称已完成MCP协议接入）；凭据仅服务端受限配置。
- 著作目录保留出版/在线体系/在写状态，章节全文索引读适配；不把在线体系全称已出版著作。
- 深脑多人原文与历史AI分析分层；不自动把未知说话人归为讲者。
- 模型提案引用实际source_id；越界引用拒绝，新增串联标为AI建议。时间草案不符目标时显式收拢并展示原始时长，实际时长待排练。
- 异步任务和明确失败状态；持久版本、基线冲突、修正后旧确认失效。
- 模型沿用已有生产provider，不接Token Plan作为网页应用后端。

## 验收
- 真实资料：能展示深脑记录及具体原文锚点、著作目录与相关章节。
- 来源失联明确告知，不以旧库或生成文字冒充获取成功。
- 没确认理解，不能进入讲述；修正理解后旧讲述不再当有效稿。
- 讲述与讲稿可审阅、修改、保存重开；不自动签收AI观点。
- 用真实校长60分钟主题跑完，核实个人/下一代/家庭不被高校治理替代。
- 来源引用可追溯，时长含互动；最终时长由排练校准。
- Python API/领域检查及浏览器操作；保留原有组课回归。

## 不做
全库重建、自动原话鉴定、自动发布、写入深脑、替用户确认立场、全库HTML转换、擅改并行生成器。

## 分工
本会话只修改备课相关新模块、prep_agent最小复用接口、应用注册与备课导航。build_index和转换/图库改动由其他会话保留。
