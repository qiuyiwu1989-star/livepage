# 架构与模块分工

## 建议方案：独立模块、连续使用流程

用户要求分析 OpenDesign Docs 的分工与合并。本方案建议保持独立模块、整合入口和版本流；这是架构建议，尚未完成接口验证或最终合并决策。

| 模块 | 主要职责 | 边界 |
|---|---|---|
| LivePage | 知识身份、课程出现位置、来源、历次讲述、证据、检索、备课与版本、播放 | 不复制一个通用设计编辑器 |
| OpenDesign Docs | 文字、布局、表格、图形、模板及动画的编辑设计 | 不成为知识身份、讲述和母课程的第二真源；实际能力待核实 |
| 转换执行器 | 提取原稿、模型候选、结构 JSON、素材和 HTML、渲染对照 | 可部署在原文件所在电脑；通过任务/制品协议交换，不依赖私人路径 |
| Echo 回声 | 用图文忠实还原某次现场讲述，保留场次与来源上下文 | 首阶段专注图文实录；与 LivePage 双向关联，不仅是单向下游输出 |
| MCP/API | 为外部 Agent 提供检索、读取、引用及授权写入 | 复用业务权限和数据契约，不直接开放私有数据库 |

预期编辑闭环：活页选择页面版本 → OpenDesign 导入 → 编辑 → 返回制品和结构 → 校验来源与编辑基线 → 追加版本 → 回到活页对照、备课和播放。先验证一页能进、能改、能保存回库，再扩大范围。HTML 存在不等于编辑器支持完整往返编辑。

## 领域对象

- Atom：稳定知识节点，不按标题相同自动合并。
- SourceVersion / PageVersion：不可变源文件与页面版本，带哈希、生成器与验收记录。
- Occurrence：某页在某课程中的出现位置，保留页号、课程和上下文；同原子不同版本不能盲目共用转换结果。
- Course / Assembly：母课程、授课草稿与固定版本；课程专属讲稿不覆盖原子通用知识。
- Session / Segment：讲述场次与原声时间段，可与页面多对多关联。自动语义匹配不是已验证翻页事实。
- Annotation / Evidence：可见原文、现场原话、AI解释、用户补充与确认分层。
- ConversionJob / Artifact / Review：任务、制品和验收分开；来源变更后旧验收失效。
- UsageEvent：引用、播放、编辑、确认不同事件，不把旧日志简单相加。

## 目标部署与当前实现

目标起步采用模块化单体：一个应用 API、后台任务执行器、结构化存储及媒体适配器。PostgreSQL、对象存储是生产方案；SQLite 可作本地适配。不是已经完成数据库迁移的声明。

目前 workbench 是文件快照与 JSON 状态适配层，仍需要私有目录和资源。个人站部署和独立仓库不应绑定：独立代码版本、明确宿主接口、独立发布与回滚。

## 转换质量约定

Keynote 原件 → PDF/高清视觉基准 → 文字/几何/素材提取 → 结构 JSON → 可编辑 HTML → 固定尺寸渲染 → 并排/叠加核验 → 修正 → 人工确认。

必须保留位置、字体、字号、换行、强调、颜色、透明度、边框、层级和图片裁切。整页位图包装不算可编辑转换。图片局部保留可以，但需明确编辑范围。先忠实还原，再做模板与动画升级。

generated、render_checked、visual_review_pending、accepted、failed 分开记录。已有 pixel-compare 标签只表示清单标记，找不到证据不能视为 accepted。投影优先已验收 HTML，其余保留原图回退。
