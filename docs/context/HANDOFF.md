# 开发接手流程

## 开工

先读本目录 README 和仓库 AGENTS.md。git fetch 后核对分支/提交和未提交改动，保留其他 Agent 的工作。不要把已有个人网站历史整体导入独立仓库。

公开仓库 workbench/README.md 说明当前适配层启动与依赖。真实课件、录音、实录、目录快照、工作区状态、字体素材、凭据不在公开仓库；缺失时明确说明，使用合成 fixture，不能伪造真实验证。

## 本机执行与另一台电脑

2026-10-14 当前开发机旧工作台相对路径 outputs/slide-library-pilot，监听 127.0.0.1:5198。本次公开发布 checkout 为 outputs/livepage-public-release；旧 livepage checkout 保留独立历史和未提交修改。以上是当前机器定位线索，不是其他平台固定路径。

转换电脑负责原始 .key 导出与 HTML 处理，先读 docs/HTML-CONVERSION-HANDOFF.md。保持原始源版本与页序，交付结构 JSON、HTML、素材、任务版本和对照报告。使用跨平台相对资源和环境配置，不将本机绝对路径作为协议。

## 同步与部署

同步三类对象分别对账：代码、结构数据、媒体/转换制品。课件和私人数据不得通过公开仓库同步。优先三方合并，来源哈希、课程出现位置、修改时间与版本共同判断；冲突保留双方，不按“本地更新”直接覆盖云端或反之。

先核实域名 DNS、真实部署目录、Git remote/commit、服务与上游、数据和对象存储归属，再备份、更新和验证。服务器连接超时须区分握手与认证阶段；没有登录证据不宣称密码错误或服务器状态。生产环境凭据不写入聊天、脚本、仓库、日志和文档。

公开代码提交通常不应触发个人站全站部署；本仓库尚无生产自动部署链路。公网发布前完成身份验证、资源访问隔离和静态文件白名单；不要把 loopback 服务改绑定公网就算上线。

## 每项任务交付要求

说明问题与修复、涉及文件、源数据/版本、验证方法和结果、未验收范围、部署状态与回滚。测试必须与变化相称；界面变化要真实检查内嵌与全屏。修改源码、结构协议或管线，而不只修一份输出掩盖批处理缺陷。

无需先重写整个产品。先选择一个真实课程和一页转换完成闭环，再逐模块替换旧适配层；新入口验收前旧数据与历史保持可读可恢复。
