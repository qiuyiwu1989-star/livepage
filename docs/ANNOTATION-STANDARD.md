# 活页 LivePage · 原子页标注与音频回流规范

版本：1.0 · 2026-10-09 · 适用：MiMo 及其他处理本库的 Agent。

本规范是处理约定。下述音频回流、字段级证据、共享解读分层是目标输出契约，不表示现有数据库/API 已全部实现。模型输出先进入独立候选目录，由导入程序校验后追加；不得把文档字段直接覆盖到现有主库。

## 1. 定义与目标

原子页是以一页 PPT 为入口，持续积累本人观点、表达方式、讲解经历和证据的知识节点。图片、HTML 是呈现形式；课程里的出现位置与历次讲解是上下文。目标是支持阅读、检索、备课组装，以及让 Agent 在有证据的前提下理解本人面对不同听众的解释方式。

一页一个稳定身份，多次使用、多次讲解持续归入。初次入库最低要求：稳定身份或明确暂定身份、可查看原页与来源、可检索标题、内容来源类别、可追加的讲解记录。没有音频或标注不阻止原件入库，不为填满字段编造内容。

## 2. 对象与身份

| 对象 | 含义 | 规则 |
| --- | --- | --- |
| atom_id | 知识节点身份 | 使用任务提供的 canonical ID，不自行改号 |
| page_id / occurrence_id | 某份课件中的出现位置 | 保留课件、页码、原始 ID；多个位置可指向同一原子 |
| page_version_id | 页面视觉/文字的具体版本 | 保留原件哈希；修改追加版本 |
| session_id | 一次授课、演讲或访谈 | 听众、日期、场合、主题属于该场次 |
| segment_id | 一段有时间定位的讲解 | 可关联多个原子；一原子可关联多段 |
| annotation_id | 一次标注/修正产物 | 追加、可追溯，不覆盖原标注 |

字体、Logo、底色、排版改变通常作为展示版本；同页在不同课件使用保存为出现位置。核心观点实质改变时保留演变关系；是否仍属同一原子由明确核验决定。相同标题、近似截图、相似语义只能产生重复候选，不能授权自动合并。原库已经存在的身份也不等于经过新一轮人工确认；遇到明显错误提出修正候选。

## 3. 内容与证据分层

每条主张必须有 source_kind、evidence_refs、review_status；缺失依据用 unknown，不用猜测填空。

- slide_text：页面中可见的原文。保留文字，不用模型润色替代。
- speaker_quote：音频可定位的本人原话。必须提供文件/资源标识、起止秒数、说话人依据。仅有 ASR 时注明未听校；不伪造逐字引文。
- ai_interpretation：模型归纳、讲解建议、推断。不能写成“邱懿武认为”或本人已确认。
- human_note：人工补充，记录提供者；不自动等同于对其他模型内容的确认。
- human_confirmed：有可追溯的本人确认记录，明确确认范围和时间。模型不得自行赋予。

review_status 使用 pending / confirmed / rejected / superseded。模型新产物固定 pending。证据包括源文件标识、版本/哈希、page_id、区域或文字片段、音频时间段。数值置信度不是人工确认；若提供 confidence，必须有 reason，不声称它是校准概率。

## 4. 标注维度

### 每次页面处理必需

- identity：atom_id、page_id、deck_id、page_number，全部来自任务输入。
- source：图片/原始文件资源引用及 sha256；无法读取则说明阻塞，不假装看过原图。
- title：原题与建议检索标题分开；不要直接覆盖旧题。
- source_text：可见文字；无法辨认部分明确标记 uncertain_spans。
- topic：一句话说明页面主题，标记是原文还是推断。
- claims：核心主张列表，每条挂证据和来源类别；没有足够证据可以为空。
- visual：画面结构、文字块、照片、图表、示意图和素材位置。
- provenance：实际模型 ID、时间、规范版本、任务 ID、输入哈希、生成方式。
- issues：漏字风险、图表读数不确定、缺图、缺来源、身份疑点等。

### 有证据再补充

知识概念、论证关系、听众收获、教学意图、前置概念、后续话题、独立使用条件、案例、引用、相关框架、相似页候选。页面复杂度、布局类型用于转换；不要为了标签齐全生成无用评分。

叙事角色、讲解建议、表达方式均是 AI 推断，除非有实际讲解证据。原库已有 reuse_score、qiu_voice_style、fits_qiu_framework 等字段原样保留出处，不自动升级为事实或确定关系。

## 5. 音频回流

顺序：保留原始录音 → 带时间戳转录 → 对齐本次课件版本/出现位置 → 建立 segment 与 atom 的关联 → 提炼该场次新增信息。

每个 segment 至少记录：segment_id、session_id、audio_ref、audio_sha256（可获取时）、start_seconds、end_seconds、speaker、transcript、transcript_status、links、alignment_method、alignment_status。时间满足 0 <= start < end <= 音频时长；上下文前后片段可单独引用，不冒充当前片段原话。

links 每项记录 atom_id、page_id、page_version_id（已知时）、匹配证据。alignment_method 可为 slide_event / manual / semantic_candidate；自动语义匹配保持 pending。场次不知道日期、听众或地点时填 null。

一段可以关联多页，一页可以关联多段。允许跳页、回看、问答与题外延伸。没有翻页记录不能伪造精确翻页时间；语义对齐先作为候选，保留修改关联和起止时间的能力。说话人无法确认时不能把听众提问或其他讲者发言归为本人观点。

按场次分别保留：讲解重点、案例、比喻、设问、铺垫、转折、听众反馈（确有记录时）、观点修订。不要将五次讲课覆盖成一段最终摘要。

## 6. 共享知识与本人讲法

共享解读挂原子；特定课程的讲法挂场次/出现位置。跨场次总结引用所有支撑片段，并记录适用听众、情境、例外和时间范围。只有一次讲解时不能宣称“惯常讲法”；无多场次证据时不得称“稳定观点”。

保留分歧、反例、旧说法和后续修正；新的说法不自动废弃旧说法。区分复述、假设、反问、引用他人和本人立场。目标是学到如何选取解释路径，而不是模仿口头禅或编造第一人称经历。

Agent 调用时同时取核心主张、证据、适用情境、相关场次与未解决分歧；需要原话则返回可定位引文，需要讲稿则明确是基于资料生成的新草稿。

## 7. HTML 转换

先理解结构，再生成可编辑初稿。文字用真实文本；简单图形用 SVG/CSS；照片优先引用已提取原素材。复杂图表可以保留为图像并标明 image_preserved，不得虚构数值重绘。整页图片包进 HTML 只能标记 image_wrapper，不能称可编辑转换完成。

保留纵横比、信息层级、关键位置、图文关系和全部有意义内容。常用字体：思源宋体、思源黑体、阿里巴巴普惠体；主题可用米色或淡蓝；Logo 使用提供的真实资产，不生成近似品牌图。规范化主题另存版本，不悄悄改写忠实还原稿。缺字体/Logo/素材时记录缺口。

每个视觉块记录 block_id、type（text/image/chart/diagram）、bbox（左上为原点，0–1归一化）、source_ref、editable 与 limitation。生成的 HTML 不含远程脚本或主动上传行为。当前回库有自包含资源、5 MiB、来源/版本 meta 等约束，必须遵守 当前宿主的编辑交接接口与真实后端校验（独立仓库适配尚待迁入）；旧页未接回库接口时只产出候选，不伪造交接票据。

必须渲染截图并与原图对照：漏字/改字、数字与单位、图片缺失、遮挡溢出、比例、字体、阅读顺序、实际可编辑性。修正后重新渲染。无法渲染时状态为 render_pending，不能声称验收通过。

## 8. 产物与状态

独立目录：jobs/<job_id>/<atom_id>/；重试放入其 runs/<run_id>/ 子目录，保留之前产物。建议文件：annotation.json、segments.json（有音频时）、slide.html、render.png、qa.json。job_id 和 atom_id 必须由任务清单给定；演示数据不得混入真实批次。

阶段独立记录：annotation、audio_alignment、html、visual_qa、human_review。每阶段使用 not_requested / pending / running / succeeded / failed / blocked；human_review 使用 pending / confirmed / rejected。HTML 已生成、截图已生成、人工已确认是不同事实，不以一个总“完成”覆盖。

失败记录原因、受影响对象、可重试阶段。重试只追加新运行记录，输入哈希与规范版本不变时可复用已完成结果。任务运行时长、调用成本仅在有真实计量时记录。

## 9. 现有库兼容

旧系统读取入口见原工作台的 agent-library.json；独立仓库 API 尚待迁入。优先使用 effective_vlm_annotation；保留 original_atom_detail、历史 annotation 和 framework_links 的原始证据。原库 narrative 可映射为 AI 讲解建议，不可映射为 speaker_quote。source_record_without_index_membership 是孤立来源，不能发明课程归属。

新标准字段先写候选 sidecar 文件；当前 page notes API 是出现页附注，不等于共享原子知识或已实现的音频关系表。既有 ID、用户笔记、组课历史、原始快照不得覆盖。不得把本规范当作生产部署或外部发布指令。

## 10. 验收清单

- 输入页与输出 ID 一一可追溯，没有未经确认的合并。
- 原图、原文、旧注释和历次讲解都可恢复。
- AI 推断与本人原话分开，每条核心主张有证据或明确缺证。
- 音频引用时间有效、说话人归属明确、自动对齐未冒充人工确认。
- HTML 的可编辑范围明确，截图已实际检查；未完成项诚实标记。
- JSON 可解析；所有引用存在或标明缺失；没有凭据、临时签名链接进入产物。
- 先完成代表性小批次，再按实际质量扩大。默认试跑12页，具体页由任务清单指定。

旧系统的提示词与样例另行保留；本仓库不携带真实标注。
