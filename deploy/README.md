# 独立活页服务与宿主接入

当前生产方案：一个 LivePage 服务、一套业务 API、一个持久写入目录。发布目录可切换，旧代码用于回滚，不再作为另一套可写产品。OpenDesign 使用自己的服务和领域数据，未来通过版本交接协议集成。

- 服务入口：workbench/run_production.py，Gunicorn 只绑定 loopback。
- 参考 systemd 单元：livepage.service.example。部署时按实际目录修改，服务账号与目录权限由宿主配置。
- 宿主将 /admin/livepage/ 代理至服务，并剥离该前缀；必须复用有效登录验证，不允许只加前端登录按钮。
- 浏览器 API 路径使用 /admin/livepage/api/。JSON 资源 URL 由响应适配器添加前缀；send_file 静态 JSON 不在响应中解码，部署时调整其资源引用。
- /opt/livepage/current 指向一个 release。可写 data 指向 /opt/livepage/state/data，未来发布禁止重新初始化、复制覆盖已有状态。
- 原始媒体和历史来源保持不变，通过适配器引用；不得将真实资源放入公开仓库。
- 老首页/详情/备课入口重定向到新版；老备课保存接口停止写入，保留历史方案只读。包含实录选段的方案不能静默转为纯幻灯片方案。
- 必须核验访问权限、真实源路径、导入课程、保存/重开/排序/讲稿/版本历史、资源加载与回滚。

2026-10-14 已在宿主首次安装独立服务。现有个人站的纯静态 Actions 发布不能自动更新 /opt 下服务或 Nginx 配置；本仓库尚无自动服务发布工作流。后续需要统一发布脚本，而不是再复制一套产品。
